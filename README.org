#+title: org-moor
#+options: toc:2 num:nil

Bring what drifts past into your own harbour, and tie it to a heading.

* Why

Most of what a day hands you arrives in pieces: a chat message with no
background, a mail whose minutes are an attachment, a link to a file on a
shared drive, a manual of two hundred pages of which three matter.  The
places they arrive in are poor places to keep them.  Their search does not
find what you remember, and the names people give files and folders do not
help it.  What you can rely on is your own environment.

Bringing a thing in is not the end of it.  A file kept is only data; it
becomes information when you have read it and written down what it means,
in sentences you would stand behind.  And information is only worth having
if you can get back to it -- to what you wrote, to the file it came from, to
the place in that file, to where the file was in the first place -- in
seconds, whenever you are asked, however long it has been.

So this package does five things, and none of them is to organise:

| Step   | What it does                                                        |
|--------+---------------------------------------------------------------------|
| Take   | bring a thing in when you meet it, which is usually outside Emacs   |
| Write  | write what it means, in the heading, beside the source as you read  |
| Tie    | join what you wrote to the source, and to the place inside it       |
| Return | get back to the heading, to the copy, to the place, to the origin   |
| Re-tie | link a source from anywhere else, retitle it, or let its copy go    |

What the package fixes is what holds these together: a link from what you
wrote to the source, and where sources are kept.  What you write, where,
and how you arrange it under a heading is yours; there are no prescribed
sections, and no heading has to be a source's.

* Install

org-moor needs [[https://github.com/yoshzucker/org-dock][org-dock]], which takes a heading out to be written in.

#+begin_src emacs-lisp
(use-package org-moor
  :straight (org-moor :host github :repo "yoshzucker/org-moor"
                      :files ("*.el" ("script" "script/*")))
  :defer t
  :commands (org-moor-take-clipboard org-moor-take-file org-moor-take-url
             org-moor-noter org-moor-insert-place org-moor-jump
             org-moor-sweep org-moor-set-title org-moor-set-origin
             org-moor-set-copy)
  :init
  (with-eval-after-load 'org-protocol
    (org-moor-protocol-setup)))
#+end_src

Programs it calls when they are there, and does without when not:

| Program     | For                                                   |
|-------------+-------------------------------------------------------|
| ~monolith~  | keeping a web page as one HTML file, with its images  |
| ~curl~      | downloading a file, or a page's HTML without monolith |
| ~pandoc~    | making HTML, Word, PowerPoint, EPUB readable as text  |

For a browser, ~script/org-moor-bookmarklet.txt~ is a bookmarklet that
sends the page through ~org-protocol://moor~.  org-protocol has to be
loaded when it arrives; see its own documentation for registering the
protocol with your system.

What you want to take is usually in front of you outside Emacs.
~script/org-moor-front.macos~ and ~script/org-moor-front.ps1~ take the
document in front -- a file open in an app, a file selected in the file
manager, a page in a browser -- once, from a global hotkey, and exit.
Each asks the app what it has open and sends it through org-protocol.
On Windows, a PowerPoint or Excel document opened from the web is saved as
a copy by the app itself, which is taken with its URL as the origin; a
Word document from the web, which cannot be copied that way, is taken as
its URL.  A file open in a browser is taken as the file: one on disk by
its path, and one in SharePoint or OneDrive -- PowerPoint for the web, a
PDF in its viewer -- by having the browser, which is signed in, download
it; Emacs asks for the title meanwhile, and takes the file from the
Downloads folder once it is whole, its URL kept as the origin.

What a URL is, Emacs tells by what it sends, not by how it is spelled: a
page is kept as a page, and a file -- a PDF behind ~/download?id=3~ --
under the name the server gives it, else its URL's, with the extension
its type has.  A page sent where a file was asked for, as a sign-in page
is, is not kept.

A page behind a sign-in -- a wiki, Confluence -- is fetched as you when
~org-moor-cookie-file~ holds your browser's cookies, written out in the
cookies.txt format by a browser extension; curl and monolith are both
given them.  Cookies run out, so the file is to be written again now and
then, and kept where only you can read it, since it is your sign-in.
On Windows, the script asks the browser itself to keep what some sites
keep behind a sign-in -- a file in SharePoint, a Confluence page as a
PDF, a page that only an extension such as SingleFile saves whole -- by
sending it to a URL that downloads it, or typing the extension's
shortcut; the copy is taken from the Downloads folder once it is there.
Which sites those are is a table of URL patterns in
~~/.config/org-moor/front.json~, a row each.  ~script/org-moor-front.json~
is read while there is none, and is its template:
~org-moor-front.ps1 -WriteConfig~ writes it there to be changed.

Following a link opens the source's copy as a ~file:~ link to it would
be opened: as ~org-file-apps~ says, in Emacs with ~C-u~, and in the
program the system opens it with on ~C-u C-u~.  A link to a place opens
the copy in Emacs at the place, since only there can it be sought: a
page of a PDF, a line, or a text in a page, which EWW shows.  When there
is none -- it is
still arriving, or could not be kept -- the original is opened, and the
echo area says so, so that you know it is not a copy you are in.
A copy that could not be kept is said so in the echo area when it fails;
downloaded by hand, the file is given to the source with
~org-moor-set-copy~, on a link to it or in Dired.

The settings most worth giving:

- ~org-moor-sources-directory~: where sources are kept.
- ~org-moor-move-directories~: where things pile up; files there are moved
  when taken, and listed by ~org-moor-sweep~.
- ~org-moor-directory-roots~: where ~org-moor-put-away~ offers to put files.
- ~org-file-apps~, Org's: which copies Emacs reads, and which the system
  opens.
- ~org-dock-agent-function~, org-dock's: an agent to help write a heading.

* Commands

| Command                   | Does                                                      |
|---------------------------+-----------------------------------------------------------|
| ~org-moor-take-clipboard~ | take the clipboard's text or image                        |
| ~org-moor-take-file~      | take a file (in Dired, the one at point)                  |
| ~org-moor-take-url~       | take a web page                                           |
| ~org-moor-noter~          | read a source beside its heading; ~i~ notes, ~q~ is done  |
| ~org-moor-insert-place~   | note the place being read, in the heading it is read for  |
| ~org-moor-jump~           | back to any heading something was taken to                |
| ~org-moor-open-source~    | open a source's copy, as following its link does          |
| ~org-moor-open-origin~    | open where a source came from                             |
| ~org-moor-set-title~      | give a source another title                               |
| ~org-moor-set-origin~     | give the sources in the region (or at point) an origin    |
| ~org-moor-set-copy~       | give a source a file as its copy (one downloaded by hand) |
| ~org-moor-sweep~          | what piled up, as one Dired buffer, newest first          |
| ~org-moor-put-away~       | move files into a directory of yours (and take them)      |
| ~org-moor-prune~          | choose which copies to let go                             |

With a prefix, the taking commands ask for the heading even in Org.

* Words

Five words carry the weight, and they are kept apart on purpose.

- a *heading* is always one of yours, in any of your Org files.  The
  package writes into it; it does not decide where it lives.
- a *source* is something you took in: a web page, a file, what was on
  the clipboard -- a message, a screenshot.  It has an /origin/ -- where
  it was when you met it, a URL or a path -- which is kept even after the
  origin changes or disappears.
- a *copy* is a source's bytes, kept with it.  A source may have no copy
  (a URL you only link to) or lose it (a copy let go); its origin and what
  you wrote about it remain.
- the *sources directory* is where sources are kept, a directory each,
  named by the source's id.  Nothing in it is meant to be arranged by
  hand: it is reached from Org, the way a database is reached through its
  queries, which is what spares you from filing.
- a *place* is a position inside a source -- a page, a line -- that a note
  points to.

A *note* is what you write.  It is plain Org under a heading, and the
package does not look inside it, except to find where it points.

* Structure

** A source is a directory

Each source is a directory of the sources directory, named by its id as
~org-attach~ names its own: the id's first two characters, and the rest
below them.  In it are its copy and its record, ~moor.org~, which says what
it is in a property drawer and a title:

| Property      | Holds                                                    |
|---------------+----------------------------------------------------------|
| ~MOOR_ORIGIN~ | where it was: a URL, or the path it was taken from       |
| ~MOOR_VIA~    | how it arrived: ~web~, ~file~, ~mail~, ~chat~, ...       |
| ~MOOR_FILE~   | the copy's file name, if it has one                      |
| ~MOOR_TAKEN~  | when it was taken, an inactive timestamp                 |

#+begin_example
sources/6f/1c.../manual.pdf
sources/6f/1c.../moor.org

:PROPERTIES:
:MOOR_ORIGIN: https://example.sharepoint.com/.../manual.pdf
:MOOR_VIA:    chat
:MOOR_FILE:   manual.pdf
:MOOR_TAKEN:  [2026-10-17 Sat 10:12]
:END:
,#+title: Approval manual 2026
#+end_example

What you write points to a source with a ~moor:~ link, from any heading,
or from a property, as often as you like; a heading may link to many
sources, and a source be linked from many headings.  A link is named by
the source's title, since no heading says which source it is:

#+begin_example
,* Expense approval, new rules
[[moor:6f1c...][Approval manual 2026]]
Approval goes to the department head before finance.
[[moor:6f1c...::12][Approval manual 2026 p. 12]]
#+end_example

Such a link is written as any Org link is: ~C-c C-l~, ~moor:~, and the
source is chosen by its title, the newest taken first; it is named by the
title, and a place added after ~::~ by the title and the place.

The record is the source's, so it goes where the copy goes, and whatever
is written about the source in Org can be moved, rewritten or thrown
away without losing where it came from.

** What is copied

A message in a chat, a paragraph of a mail, a screenshot: what reaches
you only on the clipboard is a source too, its text kept as a ~.txt~ file
and its image as a ~.png~, named after its title.  So it is kept, read
and linked as any file is -- an agent a heading is handed over to reads
it with the rest -- and its places are lines, as any text's are.

#+begin_example
sources/a3/09.../Chat from Robin.txt
sources/a3/09.../moor.org

:PROPERTIES:
:MOOR_ORIGIN: https://chat.example.com/.../message/1729
:MOOR_VIA:    chat
:MOOR_FILE:   Chat from Robin.txt
:MOOR_TAKEN:  [2026-10-17 Sat 10:12]
:END:
,#+title: Chat from Robin
#+end_example

A quote block written by hand, or an image yanked with Org's own
~yank-media~, is still yours to use; it is only not a source.

** Places

A place is written ~moor:ID::N~: page N of a PDF, or line N of any other
copy -- one read as text, see ~org-moor-text-extensions~, or what a copy
was made readable as.  A copy is not changed once taken, so its lines
stay where they were.  Following the link opens the copy there; without a
copy, the origin.  A ~moor:ID~ link with no place is the source itself.
A link of a few words, ~moor:ID::TEXT~, as places were written before,
still finds them by searching.

** Taking

~org-moor-take-file~, ~org-moor-take-url~ and ~org-moor-take-clipboard~ ask
for a title -- the file's name, the page's, what was sent with it, who
said what -- and write a link named by it, on a line of its own: at point
in Org, after the line it is on, or at the end of the heading's own text
when point is on a heading.  The source goes
in the sources directory of that file.  From outside Org, or with a
prefix, a heading is asked for.  A heading taken out by org-dock is
written in its copy.

~org-moor-take-file~ moves a file that is in one of
~org-moor-move-directories~ -- where things pile up, such as downloads --
and copies one from anywhere else, where it is in somebody's place for
it.  ~C-u C-u~ turns that round for one file.  In Dired it takes the file
at point.

~org-moor-take-clipboard~ takes the text on the clipboard, or the image;
when there are both, as there are for cells copied from a spreadsheet,
it asks which.  Emacs reads an image from the clipboard on most systems;
on macOS it is read through AppleScript, and on Windows through
PowerShell when Emacs has none.  With a prefix it also asks how the thing
arrived and where it came from -- a link to the message, which most chat
and mail programs can copy -- since the clipboard does not say.

** Picking a heading, or a directory

Wherever a heading is asked for, an existing one can be picked or a new
one made in the same prompt: a name from ~org-moor-take-targets~ --
~org-refile-targets~ unless set -- is that heading, ~PARENT/NAME~ makes
NAME under PARENT, any other name makes a top-level heading in the
inbox, and nothing makes one there titled by what is taken.  A directory is asked for the same way, under
~org-moor-directory-roots~; a path that does not exist yet is made once
you agree.

** Sweeping

~org-moor-sweep~ shows what lies in ~org-moor-move-directories~ as one
Dired buffer, newest first, so each file is decided while it is still
known.  Everything Dired does works there.  ~org-moor-put-away~ moves the
file at point, or the marked ones, into a directory of yours;
~org-moor-put-away-and-take~ also takes each from there as a copy.  A
directory is renamed as work goes on, so what Org points to is the copy
among the sources, never the directory.

** Writing, and reading beside it

A heading is written in where it is, or taken out by org-dock -- ~M-x
org-dock~ -- into a copy of its own, written back on ~C-c C-c~.  What is
noted from a source goes there.

~org-moor-noter~, on a heading, reads a source it links to, or one a
heading under it does, beside it, as org-noter does: a PDF, or a copy read
as text, opens on the left in ~org-moor-noter-mode~, and the heading on the
right, taken out to be written in.  A PDF is shown by pdf-tools when it is
there, else by DocView; a text is read-only, with its line marked.  The
keys you move with are left alone -- Evil's among them -- ~i~ notes, and
~q~ writes the heading back and puts the windows back.

~org-moor-insert-place~, ~i~ there, notes the page shown -- in a text, the
line point is on -- as a link, and the text selected, quoted under it.
They go in the heading after the line its point is on, so notes and
places alternate as you read and write.  The heading is the one beside;
for a copy opened by following a link, the heading the link was in; else
one that links to the source, asked for.  A file that is not a source yet
is taken first.  In an org-noter session it calls ~org-noter-insert-note~
instead, so one key serves wherever you read.

An agent asked to help with a heading taken out -- ~C-c C-;~ in its copy,
see org-dock -- is handed the files of the sources it links to, to read:
text, Markdown and PDF as they are, the others made readable once by
~org-moor-readable-converters~ (pandoc, to Markdown beside the copy).  It
is told which sources they are, and to cite a place as the links here do.

~org-moor-open-source~, on a heading, opens the copy of a source it, or a
heading under it, links to, the prefix as for a link;
~org-moor-open-origin~, where it came from.

~org-moor-noter~ reads the copy as Emacs can: a PDF, a text, a page in
EWW, where a place is a text selected, and Word, PowerPoint and the like
as what ~org-moor-readable-converters~ makes them, whose lines are noted
and found again.

** Titles

A source's title is in its record, out of the way, so ~org-moor-set-title~
gives it another: on a link to it, in a copy of it, or on a heading
linking to it.  The links in the buffer named by the old title are named
by the new one, their places kept; links elsewhere keep their names,
which are only names.

** Letting copies go

~org-moor-prune~ lists the sources with a copy, largest first, with when
each was taken, whether its origin is a URL, and whether anything still
links to it.  ~d~ marks, ~u~ unmarks, ~x~ lets the marked ones go: the
bytes are deleted, and the record, with the origin, stays.  ~t~ sets the title,
~o~ the origin, ~RET~ opens.

** The sources directory

~org-moor-sources-directory~ holds the sources.  Keep it next to your Org
files, so that they travel together, and out of everyday search: a
directory of PDFs and slides makes a text search slow, and is better
searched on purpose, with a tool that reads such files.  Its records are
Org files, but not notes: leave it out of whatever gathers your notes.

A file can keep its sources apart -- a document's, in a directory of its
own -- by a function in ~org-moor-sources-directory-functions~, which says
where a file's sources are.  A link is followed in the sources of the
file it is in, and failing that in ~org-moor-sources-directory~.

Images that are part of what you write -- a screenshot, a figure -- are not
sources: they have no origin elsewhere and belong with ~org-attach~ as
before.
