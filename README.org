#+title: org-moor
#+options: toc:2 num:nil

Bring what drifts past into your own harbour, and tie it to a heading.

* Why

Most of what a day hands you arrives in pieces: a chat message with no
background, a mail whose minutes are an attachment, a link to a file on a
shared drive, a manual of two hundred pages of which three matter.  The
places they arrive in are poor places to keep them.  Their search does not
find what you remember, and the names people give files and folders do not
help it.  What you can rely on is your own environment.

Bringing a thing in is not the end of it.  A file kept is only data; it
becomes information when you have read it and written down what it means,
in sentences you would stand behind.  And information is only worth having
if you can get back to it -- to what you wrote, to the file it came from, to
the place in that file, to where the file was in the first place -- in
seconds, whenever you are asked, however long it has been.

So this package does five things, and none of them is to organise:

| Step   | What it does                                                         |
|--------+----------------------------------------------------------------------|
| Take   | bring a thing in when you meet it, which is usually outside Emacs    |
| Write  | write what it means, in the heading, beside the source as you read   |
| Tie    | join what you wrote to the source, and to the place inside it        |
| Return | get back to the heading, to the replica, to the place, to the origin |
| Re-tie | link a source from anywhere else, retitle it, or let its replica go  |

What the package fixes is what holds these together: a link from what you
wrote to the source, and where sources are kept.  What you write, where,
and how you arrange it under a heading is yours; there are no prescribed
sections, and no heading has to be a source's.

* Install

org-moor needs [[https://github.com/yoshzucker/org-dock][org-dock]], which takes a heading out to be written in.

#+begin_src emacs-lisp
(use-package org-moor
  :straight (org-moor :host github :repo "yoshzucker/org-moor"
                      :files ("*.el" ("script" "script/*")))
  :defer t
  :commands (org-moor-take-clipboard org-moor-take-file org-moor-take-url
             org-moor-noter org-moor-insert-place org-moor-insert-quote
             org-moor-jump org-moor-sweep org-moor-set-title
             org-moor-set-origin org-moor-set-replica org-moor-keep-replica
             org-moor-awaiting)
  :hook (org-mode . org-moor-eldoc-setup)
  :init
  (with-eval-after-load 'org-protocol
    (org-moor-protocol-setup)))
#+end_src

org-moor fetches nothing.  It never reaches out to a network, nor runs a
program that does: what comes from the web is what your browser saved,
when you had it open it.  So there is no question of whom a page was
fetched as -- it was you, in your browser, looking at it -- and nothing
an agent hands it is opened behind your back.

Programs it calls when they are there, and does without when not:

| Program     | For                                                         |
|-------------+-------------------------------------------------------------|
| ~pandoc~    | making HTML, Word, PowerPoint, EPUB readable by a machine   |
| ~pdftotext~ | finding the page words are on, and words in a PDF           |

For a browser, ~script/org-moor-bookmarklet.txt~ is a bookmarklet that
sends the page through ~org-protocol://moor~.  org-protocol has to be
loaded when it arrives; see its own documentation for registering the
protocol with your system.  To save a page whole, as it is seen, the
browser wants the SingleFile extension.

What you want to take is usually in front of you outside Emacs.
~script/org-moor-front.macos~ and ~script/org-moor-front.ps1~ take the
document in front -- a file open in an app, a file selected in the file
manager, a page in a browser -- once, from a global hotkey, and exit.
Each asks the app what it has open and sends it through org-protocol.
What arrives goes where Emacs was left: at point when the buffer in front
is Org, as if taken there; otherwise a heading is asked for.
On Windows, a PowerPoint, Word or Excel document opened from the web is
saved by the app itself, and the file is taken with its URL as the
origin.  A message in Outlook -- open in its window, or selected in the
list -- is saved as a ~.msg~ and taken.  A file open in a browser is
taken as the file: one on disk by its path, and one in a document
library on the web -- PowerPoint for the web, a PDF in its viewer -- by
having the browser, which is signed in, download it.  A page open in a
browser is taken as the page you save of it, with SingleFile.

** The web

A page or a file on the web is taken by its URL, and its source has its
origin alone at first: its replica is awaited.  ~org-moor-take-url~
opens the URL in the browser you read in -- ~browse-url~ -- and waits
for what the browser saves into ~org-moor-downloads-directory~: the page
you save with SingleFile, or the file it downloads.  A page in front,
taken from outside Emacs, is open already, and is only waited for.  A
file come there whole is asked about before it is taken -- ~Take
deck.pptx as the replica of Plan?~ -- since what else arrives there
meanwhile is not told from it otherwise; one said not to be it is passed
over.  It is waited for until it is taken, or ~org-moor-stop-waiting~,
with no time limit, and the mode line says which replica is waited for.
One is waited for at a time.

Some sites keep a file behind a viewer -- a document library, a wiki
that exports its pages -- whose download is at another URL.  On Windows,
~~/.config/org-moor/front.json~ says which: under ~sites~, an entry -- one
~{ }~ -- for each URL pattern, its ~match~ a regular expression for the
URL, and its ~download~ the URL to send the browser to, ~{name}~ in it
the group of that name in ~match~; and ~title~, when given, what the site
adds to the window's title, taken off.  A URL gets the first entry whose
~match~ fits it.  ~script/org-moor-front.json~ is read while there is
none, and is its template: ~org-moor-front.ps1 -WriteConfig~ writes it
there to be changed.  A URL Emacs opens is looked up in the same
entries, through ~org-moor-browser-url-function~: the URL is only
spelled differently there, and the browser is what goes to it.

~org-moor-awaiting~ lists the sources whose replicas are awaited -- those
linked in the region, at point, under the heading, or in the whole file
before its first heading -- with when each was asked for; ~RET~ opens
one in the browser, and waits for its replica.  ~org-moor-keep-replica~
lists those on the web so, and takes again from where they are those
whose origin is a file.

** Agents

An agent working on a heading taken out by org-dock is told how to cite
a source, and a command that takes one in, which prints the link, the
file to read, and the replica.  A file the agent fetched itself is
taken as the replica, with ~--origin-url~ for where it is seen -- a
document's page in its library, not the API it was fetched by.  A URL is
awaited from you: nothing is fetched for the agent, which is told there
is nothing to read yet, and is to write nothing the source says.  The
Emacs you work in says an agent took it, while its server is running; a
URL already awaited is not taken a second time.  ~--machine-readable~ is
a file the agent fetched that a machine reads better than the replica --
an API's XML for the same page -- with ~--machine-readable-url~, where it
came from: the agent reads that, and you check against the replica.

The agent is told to quote what a source says, and to check each quote
is in the replica, as it is seen, by another command, which prints
~Found~ or ~Not found~.  Words are found however their whitespace and
width differ, and words left out, marked ~…~, split them into parts
found in turn.

A source is not taken to a heading out in a copy that an agent is
writing, whose buffer is read-only meanwhile: nothing is made, and the
echo area says why.

** Following a link

Following a link opens the source's replica as it is seen: a PDF and a
text in Emacs, a page in the browser, anything else in its program, by
~org-file-apps~ as a ~file:~ link is; in the program the system opens
it with on ~C-u C-u~.  A link to words opens the replica at them: a PDF
at the page they are on, a text at them, and a page in the browser at
them by a text fragment, ~#:~:text=~, where the browser goes to words.
Wherever the words cannot be shown -- a document in Word, a browser that
does not go to them -- they are put on the clipboard, to be found, and
the echo area says so.  When there is no replica yet, the origin is
opened, as it is now, and the echo area says so.  A file downloaded by
hand is given to a source with ~org-moor-set-replica~, on a link to it
or in Dired.
Whether a source has its replica is said before the link is followed:
with point on a link, ~org-moor-eldoc-setup~ on ~org-mode-hook~ has the
echo area say the replica and its size, or that it is awaited, how and
when it came, what a machine reads of it, and its origin; the mouse
over a link says the same.

The settings most worth giving:

- ~org-moor-sources-directory~: where sources are kept.
- ~org-moor-move-directories~: where things pile up; files there are moved
  when taken, and listed by ~org-moor-sweep~.
- ~org-moor-downloads-directory~: where the browser saves, where a replica
  is waited for.
- ~org-moor-directory-roots~: where ~org-moor-put-away~ offers to put files.
- ~org-file-apps~, Org's: which replicas Emacs reads, and which the system
  opens.
- ~org-dock-agent-function~, org-dock's: an agent to help write a heading.

* Commands

| Command                            | Does                                                         |
|------------------------------------+--------------------------------------------------------------|
| ~org-moor-take-clipboard~          | take the clipboard's text or image                           |
| ~org-moor-take-file~               | take a file (in Dired, the one at point)                     |
| ~org-moor-take-url~                | take a web page, its replica saved by the browser            |
| ~org-moor-awaiting~                | the sources whose replicas are awaited; ~RET~ opens one      |
| ~org-moor-stop-waiting~            | stop waiting for a replica                                   |
| ~org-moor-noter~                   | read a PDF or a text beside its heading; ~i~ notes, ~q~ ends |
| ~org-moor-insert-place~            | quote what is selected, in the heading it is read for        |
| ~org-moor-insert-quote~            | quote the words on the clipboard, here                       |
| ~org-moor-jump~                    | back to any heading something was taken to                   |
| ~org-moor-open-replica~            | open a source's replica, as following its link does          |
| ~org-moor-open-origin~             | open where a source is seen                                  |
| ~org-moor-open-machine-readable~   | open what a machine reads of a source                        |
| ~org-moor-clip-origin~             | put a source's origin on the clipboard                       |
| ~org-moor-set-title~               | give a source another title                                  |
| ~org-moor-set-origin~              | give the sources in the region (or at point) an origin       |
| ~org-moor-set-replica~             | give a source a file as its replica (one downloaded by hand) |
| ~org-moor-keep-replica~            | keep a replica, from its origin, of sources that have none   |
| ~org-moor-sweep~                   | what piled up, as one Dired buffer, newest first             |
| ~org-moor-put-away~                | move files into a directory of yours (and take them)         |
| ~org-moor-prune~                   | choose which replicas to let go                              |
| ~org-moor-migrate-records~         | write a sources directory's records of the old form anew     |

With a prefix, the taking commands ask for the heading even in Org.

* Words

Five words carry the weight, and they are kept apart on purpose.

- a *heading* is always one of yours, in any of your Org files.  The
  package writes into it; it does not decide where it lives.
- a *source* is something you took in: a web page, a file, what was on
  the clipboard -- a message, a screenshot.  It has an /origin/ -- where
  it is seen, a URL, a file as a ~file:~ URL -- which is kept even after
  the origin changes or disappears.
- a *replica* is the source as it is seen there, kept with it: the page,
  the document.  It is what you open to check what is said of the source.
  A source may have none yet (one awaited from the browser) or lose it (a
  replica let go); its origin and what you wrote about it remain.
- what is *machine readable* of a source is what an agent reads, when that
  is not the replica: an API's XML fetched apart, or what pandoc made of a
  document.  It is never what you check against, but it is never hidden.
- the *sources directory* is where sources are kept, a directory each,
  named by the source's id.  Nothing in it is meant to be arranged by
  hand: it is reached from Org, the way a database is reached through its
  queries, which is what spares you from filing.
- a *place* is the words a note quotes from a source, found again in any
  form of it.

A *note* is what you write.  It is plain Org under a heading, and the
package does not look inside it, except to find where it points.

* Structure

** A source is a directory

Each source is a directory of the sources directory, named by its id as
~org-attach~ names its own: the id's first two characters, and the rest
below them.  In it are its replica, what is machine readable of it, and
its record, ~moor.org~, which says what it is in a property drawer and a
title:

| Property                     | Holds                                                     |
|------------------------------+-----------------------------------------------------------|
| ~ORIGIN_URL~                 | where it is seen: a URL, a file as a ~file:~ URL          |
| ~REPLICA_FILE~               | the replica's file name, once it has one                  |
| ~REPLICA_VIA~                | how it arrived: ~web~, ~file~, ~mail~, ~chat~, ~agent~, ... |
| ~REPLICA_TAKEN~              | when, an inactive timestamp                               |
| ~REPLICA_REQUESTED~          | while it has none, when it was asked for                  |
| ~MACHINE_READABLE_FILE~      | what a machine reads of it, when that is not the replica  |
| ~MACHINE_READABLE_URL~       | fetched apart: where from                                 |
| ~MACHINE_READABLE_VIA~       | how                                                       |
| ~MACHINE_READABLE_TAKEN~     | when                                                      |
| ~MACHINE_READABLE_MADE_FROM~ | made from the replica: its file name                      |
| ~MACHINE_READABLE_MADE_BY~   | by what                                                   |
| ~MACHINE_READABLE_MADE~      | when                                                      |

A record without ~MACHINE_READABLE_FILE~ has its replica read as it is,
by a machine too.  A file is a ~file:~ URL, ~file:///C:/a.pdf~,
~file://host/share/a.pdf~ for a shared folder, written as it reads but
for ~%~.

#+begin_example
sources/6f/1c.../act.html
sources/6f/1c.../lawdata.xml
sources/6f/1c.../moor.org

:PROPERTIES:
:ORIGIN_URL:                  https://laws.example.gov/law/1
:REPLICA_FILE:                act.html
:REPLICA_VIA:                 web
:REPLICA_TAKEN:               [2026-10-17 Sat 10:12]
:MACHINE_READABLE_URL:        https://laws.example.gov/api/1/lawdata/1
:MACHINE_READABLE_FILE:       lawdata.xml
:MACHINE_READABLE_VIA:        agent
:MACHINE_READABLE_TAKEN:      [2026-10-17 Sat 10:13]
:END:
,#+title: Road Traffic Act
#+end_example

A source is what is one thing to the person reading it -- a law, not
each of its articles -- and its places are within it.

What you write points to a source with a ~moor:~ link, from any heading,
or from a property, as often as you like; a heading may link to many
sources, and a source be linked from many headings.  A link is named by
the source's title, since no heading says which source it is:

#+begin_example
,* Expense approval, new rules
[[moor:6f1c...][Approval manual 2026]]
Approval goes to the department head before finance.
[[moor:6f1c...::Approval goes to the head][Approval manual 2026 “Approval goes to the head”]]
,#+begin_quote
Approval goes to the head of the department before it reaches finance.
,#+end_quote
#+end_example

Such a link is written as any Org link is: ~C-c C-l~, ~moor:~, and the
source is chosen by its title, the newest first; it is named by the
title, and the words after ~::~ by the title and the words.  The name
is the link's words alone: nothing reads them back, so they may be
rewritten as you like.

A file whose links find their place by the quote under them -- a
function in ~org-moor-place-by-quote-functions~ says so, called with its
name -- has links with no place: the quote is the place, written once,
and the link is named where in the source it is, as the source itself
numbers it -- an article, a page, a section.  What org-moor writes there,
and tells an agent to write, is then ~[[moor:6f1c...][TITLE]]~ and the
quote.

The record is the source's, so it goes where the replica goes, and whatever
is written about the source in Org can be moved, rewritten or thrown
away without losing where it came from.

** What is copied

A message in a chat, a paragraph of a mail, a screenshot: what reaches
you only on the clipboard is a source too, its text kept as a ~.txt~ file
and its image as a ~.png~, named after its title.  So it is kept, read
and linked as any file is -- an agent a heading is handed over to reads
it with the rest -- and its places are words, as any text's are.

#+begin_example
sources/a3/09.../Chat from Robin.txt
sources/a3/09.../moor.org

:PROPERTIES:
:ORIGIN_URL:                  https://chat.example.com/.../message/1729
:REPLICA_FILE:                Chat from Robin.txt
:REPLICA_VIA:                 chat
:REPLICA_TAKEN:               [2026-10-17 Sat 10:12]
:END:
,#+title: Chat from Robin
#+end_example

A quote block written by hand, or an image yanked with Org's own
~yank-media~, is still yours to use; it is only not a source.

** Places

A place is written ~moor:ID::WORDS~: the start of the words quoted, up to
~org-moor-text-place-length~ characters, on one line.  Words are found in
any form of the source -- the page as the browser shows it, a PDF, what a
machine reads -- where a line or a page number is the form's own.  A
replica is not changed once taken, so the words stay where they were.
Following the link opens the replica at them; without a replica, the
origin.  A ~moor:ID~ link with no place is the source itself.

** Taking

~org-moor-take-file~, ~org-moor-take-url~ and ~org-moor-take-clipboard~ ask
for a title -- the file's name, the page's, what was sent with it, who
said what -- and write a link named by it, on a line of its own: at point
in Org, after the line it is on, or at the end of the heading's own text
when point is on a heading.  The source goes
in the sources directory of that file.  From outside Org, or with a
prefix, a heading is asked for.  A heading taken out by org-dock is
written in its copy.

~org-moor-take-file~ moves a file that is in one of
~org-moor-move-directories~ -- where things pile up, such as downloads --
and copies one from anywhere else, where it is in somebody's place for
it.  ~C-u C-u~ turns that round for one file.  In Dired it takes the file
at point.

~org-moor-take-clipboard~ takes the text on the clipboard, or the image;
when there are both, as there are for cells copied from a spreadsheet,
it asks which.  Emacs reads an image from the clipboard on most systems;
on macOS it is read through AppleScript, and on Windows through
PowerShell when Emacs has none.  With a prefix it also asks how the thing
arrived and where it came from -- a link to the message, which most chat
and mail programs can copy -- since the clipboard does not say.

** Picking a heading, or a directory

Wherever a heading is asked for, an existing one can be picked or a new
one made in the same prompt: a name from ~org-moor-take-targets~ --
~org-refile-targets~ unless set -- is that heading, ~PARENT/NAME~ makes
NAME under PARENT, any other name makes a top-level heading in the
inbox, and nothing makes one there titled by what is taken.  A directory is asked for the same way, under
~org-moor-directory-roots~; a path that does not exist yet is made once
you agree.

** Sweeping

~org-moor-sweep~ shows what lies in ~org-moor-move-directories~ as one
Dired buffer, newest first, so each file is decided while it is still
known.  Everything Dired does works there.  ~org-moor-put-away~ moves the
file at point, or the marked ones, into a directory of yours;
~org-moor-put-away-and-take~ also takes each from there as a replica.  A
directory is renamed as work goes on, so what Org points to is the replica
among the sources, never the directory.

** Writing, and reading beside it

A heading is written in where it is, or taken out by org-dock -- ~M-x
org-dock~ -- into a copy of its own, written back on ~C-c C-c~.  What is
noted from a source goes there.

~org-moor-noter~, on a heading, reads a source it links to, or one a
heading under it does, beside it, as org-noter does: a PDF, or a text,
opens on the left in ~org-moor-noter-mode~, and the heading on the right,
taken out to be written in.  A PDF is shown by pdf-tools when it is
there, else by DocView; a text is read-only, with its line marked.  The
keys you move with are left alone -- Evil's among them -- ~i~ notes, and
~q~ writes the heading back and puts the windows back.  Only a PDF and a
text are read so, since only they are shown in Emacs as they are seen; a
page or a document opens in its own program instead.

~org-moor-insert-place~, ~i~ there, quotes the words selected, with a
link to them.  They go in the heading after the line its point is on, so
notes and quotes alternate as you read and write.  The heading is the
one beside; for a replica opened by following a link, the heading the
link was in; else one that links to the source, asked for.  A file that
is not a source yet is taken first.  In an org-noter session it calls
~org-noter-insert-note~ instead, so one key serves wherever you read.

Reading a page in the browser or a document in its program, copy the
words, and ~org-moor-insert-quote~ in the heading quotes them, with a
link to the source the heading links to.

An agent asked to help with a heading taken out -- ~C-c C-;~ in its copy,
see org-dock -- is handed the files of the sources it links to, to read:
what is machine readable of each, else its replica.  What is machine
readable is made when the replica arrives, by
~org-moor-machine-readable-converters~ (pandoc, to Markdown beside the
replica), and recorded as made from it; ~org-moor-open-machine-readable~
opens it.  The agent is told which sources they are, and to cite by
quoting.

~org-moor-open-replica~, on a heading, opens the replica of a source it, or a
heading under it, links to, the prefix as for a link;
~org-moor-open-origin~, where it is seen.  A URL opens in the browser,
but a Word, Excel or PowerPoint document on a web server -- a document
library -- opens from there in its Office application, by the Office URI
schemes ~org-moor-office-url-schemes~ names, rather than being
downloaded.

** Titles

A source's title is in its record, out of the way, so ~org-moor-set-title~
gives it another: on a link to it, in a replica of it, or on a heading
linking to it.  The links in the buffer named by the old title are named
by the new one, their places kept; links elsewhere keep their names,
which are only names.

** Letting replicas go

~org-moor-prune~ lists the sources with a replica, largest first, with when
each was taken, whether its origin is a URL, and whether anything still
links to it.  ~d~ marks, ~u~ unmarks, ~x~ lets the marked ones go: the
bytes are deleted -- the replica and what is machine readable of it --
and the record, with the origin, stays.  ~t~ sets the title,
~o~ the origin, ~RET~ opens.

** The sources directory

~org-moor-sources-directory~ holds the sources.  Keep it next to your Org
files, so that they travel together, and out of everyday search: a
directory of PDFs and slides makes a text search slow, and is better
searched on purpose, with a tool that reads such files.  Its records are
Org files, but not notes: leave it out of whatever gathers your notes.

A file can keep its sources apart -- a document's, in a directory of its
own -- by a function in ~org-moor-sources-directory-functions~, which says
where a file's sources are.  A link is followed in the sources of the
file it is in, and failing that in ~org-moor-sources-directory~.

Images that are part of what you write -- a screenshot, a figure -- are not
sources: they have no origin elsewhere and belong with ~org-attach~ as
before.
